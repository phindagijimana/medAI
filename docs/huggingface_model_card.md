# MedAI-EPI-tuned: a LoRA adapter for structured epilepsy phenotype extraction from clinical notes

**Base model:** [`m42-health/Llama3-Med42-8B`](https://huggingface.co/m42-health/Llama3-Med42-8B)

**Adapter type:** Parameter-efficient LoRA (PEFT) — rank 16, α 32

**Release version:** v1.0 ([TBD release date])

**Framework:** [MedAI-EPI](https://github.com/[TBD]/med42_service) — evidence-grounded epilepsy phenotype extraction

---

## Model summary

`MedAI-EPI-tuned` is a LoRA adapter on top of Med42-8B that emits
schema-conformant `EpilepsyPhenotype` JSON (MedAI-EPI schema v0.2.1)
directly from a clinical document. Unlike the base model, which
frequently emits clinically-correct values in prose but rarely wraps
them in the required Evidence[T] structure, this adapter is trained
end-to-end to produce valid JSON with source-text evidence spans on
every populated field.

Deploy the adapter alongside the base weights via `peft.PeftModel`
or by setting `MEDAI_LORA_ADAPTER_DIR=<path>` in the MedAI-EPI
service; see the framework repository for detailed instructions.

---

## Training data

The adapter was trained on 1200 (prompt, schema-conformant target)
pairs drawn from:

- **Synth-v1 (n=1000)** — 500 synthetic epilepsy patients × 2 rendered
  documents each (progress note + MRI/EEG report), generated by
  OpenAI GPT-5.6-sol under a semantic-plan-constrained prompt. Targets
  are deterministic derivatives of a sampled G0 phenotype (schema-
  conformant Evidence[T] structures). Released alongside this adapter
  on Zenodo (DOI [TBD]).
- **Fonferko-Shadrach 2024 (n=200)** — clinician-authored epilepsy
  clinic letters with our v0.2.1 silver targets derived from the
  authors' original character-anchored annotations (Zenodo records
  8381080, 8356494, 8382589, 12520180; CC-BY 4.0).

**Held out from training:** the 60-document EpiSynth pilot corpus, used
as an untainted evaluation set. Patients were split 90 / 10 into
training and validation with no patient's documents straddling the
split (validation set: 122 pairs).

## Training configuration

- **Method:** QLoRA-style LoRA fine-tuning (bfloat16 mixed precision,
  4-bit quantized base) via `peft`.
- **LoRA rank / alpha / dropout:** 16 / 32 / 0.05
- **Target modules:** attention (q/k/v/o_proj) and MLP
  (gate/up/down_proj) projections on every transformer layer.
- **Trainable parameters:** 41,943,040 out of 8,072,204,288 (0.52%).
- **Optimizer:** AdamW; **LR:** 3 × 10⁻⁴; **schedule:** cosine with
  10 % warmup; **weight decay:** 0.01.
- **Batch:** per-device 1 × grad-accum 8 = effective 8.
- **Epochs:** up to 5 with validation-loss early stopping (patience 2)
  and `load_best_model_at_end`.
- **Loss masking:** labels set to `-100` on prompt-position tokens so
  gradients flow only from target-JSON positions (QLoRA / Han-2021
  convention).
- **Hardware:** NVIDIA L40S 24 GB slice, single GPU.
- **Wall-clock:** 82.1 min (4,928 s train_runtime).
- **Best checkpoint:** epoch 3, validation loss 0.00952 (per-epoch
  trajectory 0.01008 → 0.00979 → **0.00952** → 0.00958 → 0.01030).
- **Seed:** 0.

## Intended use

- **Yes** — extracting structured `EpilepsyPhenotype` JSON from
  epilepsy clinic letters, MRI reports, EEG reports, or progress notes
  for research phenotyping pipelines; downstream use in epilepsy
  cohort assembly; reproducibility of published MedAI-EPI results.
- **No** — clinical decision-making; direct patient-facing use;
  extraction from non-epilepsy specialties (out of training
  distribution); languages other than English.

## Limitations and bias

- **Synthetic-training bias.** 1000 of 1200 training pairs were
  synthetic (GPT-5.6-sol-generated). While the generator was
  constrained by a semantic-plan prompt that forbids inventing
  unlicensed content, generator idiosyncrasies (word choices, section
  ordering, ambiguity handling) can leak into the adapter. The 200
  clinician-authored Fonferko-Shadrach letters in the training set
  partially anchor the adapter to real prose, but evaluations on a
  novel institutional corpus are recommended before deployment.
- **English-only.** Training data is entirely English clinical prose.
  Performance on non-English notes has not been measured; assume
  unusable without fine-tuning.
- **Schema-scoped.** The adapter emits MedAI-EPI schema v0.2.1
  (six modules: `document`, `clinical_seizure`, `medication`,
  `clinical_localization`, `eeg`, `mri`, `integrated`). Fields outside
  this schema are not extracted.
- **Rare-phenotype coverage.** The G0 sampler over-samples rare
  phenotypes (~20 %) to increase adapter exposure, but tail entities
  (e.g. certain surgical-history phrasings, unusual etiology
  qualifiers) remain undersampled relative to natural incidence.
- **No adjudication against clinician-generated schemas.** All
  training targets are deterministic derivatives of G0 phenotypes;
  they were not adjudicated by an epilepsy specialist against the
  rendered prose. Downstream users should treat adapter output as
  silver-level phenotyping until validated on their own gold.

### Fairness statement

The G0 sampler was designed to match ILAE-2017 population priors on
epilepsy type, drug resistance, and etiology category. It does NOT
sample explicit demographic attributes (age, sex, race, ethnicity,
socioeconomic status, insurance, language proficiency). Consequently,
the adapter's fairness across demographic subgroups has not been
measured; users deploying this adapter on a real cohort MUST perform
subgroup-stratified error analysis before assigning phenotypes at
scale. Real-world epilepsy datasets exhibit known disparities in
documentation completeness, treatment access, and outcome reporting
across race, insurance, and rurality axes — an adapter trained
primarily on synthetic data cannot correct for these and may
inadvertently amplify them if downstream cohort assembly conditions
on adapter-extracted features. Please open an issue on the framework
repository with any subgroup findings so the research community can
build a shared fairness picture.

## How to use

Basic PEFT loading (Python, `transformers` + `peft`):

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

base = AutoModelForCausalLM.from_pretrained(
    "m42-health/Llama3-Med42-8B",
    torch_dtype="bfloat16", device_map="auto",
)
tok = AutoTokenizer.from_pretrained("m42-health/Llama3-Med42-8B")
model = PeftModel.from_pretrained(base, "[TBD hf-repo-id]")
model.eval()

# … then run the MedAI-EPI prompt registry against `model`.
```

Or via the MedAI-EPI framework:

```bash
MEDAI_LORA_ADAPTER_DIR=/path/to/adapter \
MEDAI_CONSTRAINED=1 \
python scripts/medai_epi_cli.py extract \
    --doc-type progress_note --arm M2 note.txt
```

See the framework README (`README.md` §Fine-tuned mode) for full
usage.
